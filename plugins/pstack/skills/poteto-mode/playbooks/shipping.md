### Shipping

**You own what lands. Verify each PR independently, land only the verified run from the root, then keep hands off the stack.** Babysit makes the chain merge-ready. Shipping determines what is safe to land, under the operator's explicit merge authorization.

1. **Verify each PR independently before landing.** GitHub CLI (`gh`) is the default. Use one available Codex verifier per PR to exercise the real user surface, parent against head, and return `PASS`, `PASS+NOTES` or `FAIL`. Publish verdicts only when comments are authorized; otherwise preserve them locally. The verifier must not have written the code. Green CI and bot approval are not verdicts. No subagent support means reduced independence, disclosed rather than claimed.
2. **Land only the contiguous verified run from the bottom.** Stop at the first PR without a passing verdict. The PR immediately below it is the ceiling. A verified PR above a gap waits. An independent patch can move to trunk separately only with authorization and a fresh verdict, because its prior proof included the code below it.
3. **Recheck exact patch and base freshness.** Record verdict head SHA, base SHA and stable `git patch-id` for the base-to-head diff. Compare the current patch before reusing a verdict. For changes only in tests, docs or lint config, compare each lane's build twice at the verdict SHA and once at the current head. A difference is noise only if it already occurs between the two old builds or is an embedded commit SHA. Report each noise category and files. Re-run fresh checks and review the changed content. A live lane without comparable build output cannot prove reuse and must rerun. Reverify all other drift.

   **Base freshness takes precedence over patch-id or build-noise reuse.** If trunk or the intended parent/base changes, rerun CI and required live/perf lanes against the combined current base and PR head, and refresh exact base/head receipts. A clean merge and non-overlapping paths do not establish integration safety. A forge's green merge-queue or latest-merge result is equivalent only when it identifies that exact combined tree and includes the required live/perf evidence. Green checks on a stale head are not equivalent.
4. **Land bottom-up, one PR at a time.** Merge only the lowest unmerged verified PR whose live base is trunk, using `gh pr merge <pr> --squash` under explicit authority. A child still targeting its parent would merge into that branch and collapse the chain. Read back `gh pr view <pr> --json state,mergedAt,baseRefName`; a queued or auto-merge request is not a landed PR. Confirm merged state with trunk as base before moving on.

   After a confirmed merge, the designated topology writer may retarget the next child's base to trunk with `gh pr edit <pr> --base <trunk>` and move its patch onto the merge result. Publishing a rewritten head requires explicit authority, exclusive ownership and `--force-with-lease` pinned to a verified remote SHA. Refresh receipts and apply step 3 before its merge. Never arm auto-merge on a child targeting an unprotected parent. An authorized root auto-merge request must cover the current verified head, but remains a request until live merged state confirms landing.
5. **Observe the drain without competing writers.** The coordinated next-link move is the only topology change during landing. Use the self-contained `scripts/watch-pr/watch-pr.mjs` helper via Node and the queued-mode contract in `playbooks/babysit.md`. Use current Codex completion notifications or a bounded watcher, not a native recurring loop. `ADVANCE` is progress; `COMPLETE` at the verified ceiling is the exit condition. Diagnose a stall before mutating.
6. **Stop at the ceiling.** Extending the run requires new independent verdicts and a new authorized pass through step 1. Report the next gap and the proof it needs.

**Optional Graphite queue.** If the repository already uses Graphite and the operator authorized its landing workflow, it may drain the same verified run instead of manual `gh` merges. Confirm local parentage and Graphite's own queue state before `gt submit --merge-when-ready --always --update-only --no-interactive`. `autoMergeRequest` does not prove Graphite arming. Do not combine this queue with GitHub auto-merge, retargets, restacks, speculative pushes or a second topology writer. Watch only to the verified ceiling. Graphite is not required for the PR-chain frontier or the default shipping route.

**Reply:** the run and ceiling, each verdict and verifier, what landed and how it was confirmed, any queued-but-unmerged request, and what the next gap needs.
