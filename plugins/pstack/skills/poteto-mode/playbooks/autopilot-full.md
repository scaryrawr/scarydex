### Autopilot-full

**You own the verdicts, never the PRs. One owner carries each PR from build to merge. Nothing merges until independent verification proves the code that lands.**

1. **Honor the operator's gates.** A request to state the plan is not a go. Persist the full objective after explicit execution approval. The grant covers only the queue and authorized actions. Operator-owned items and work outside it stop at merge-ready. Neither autonomy nor this playbook grants merge, publication, recurring execution, or force-push authority.
2. **Give each PR one owner and a recoverable record.** Use available Codex delegation and `gh` for GitHub operations. Do not require a cloud runtime, Origin or Graphite. Each owner builds, opens its PR per `playbooks/opening-a-pr.md`, proves the real artifact, triages bot feedback skeptically, runs `/unslop` and `/no-comments`, and babysits to green per `playbooks/babysit.md`. Open authorized PRs early so checks overlap the work. Rebase onto current trunk before the code-ready report. Report the code-ready head, every later head, and merge-ready receipts.

   Keep a local, uncommitted `decisions.tsv` per **show-me-your-work**, returned with reports. Push authorized checkpoints after each verifiable unit. Record each delegate's identity, state and evidence-based stuck-after runtime in durable local artifacts. Force-push only an exclusively owned branch with explicit authority, using `--force-with-lease` pinned to the last pushed or independently verified takeover SHA. An unexpected remote push stops publication and is reported.
3. **Run independent PR owners in parallel off trunk.** One writer per branch and disjoint scope. Do not turn independent work into a stack. Coupled work routes to Autopilot-stack or serial merge-then-branch. Match supported effort controls to each job per **poteto-mode**.
4. **Independently verify the code-ready head.** Fan out per **swarm** to rerun gates, prove load-bearing behavior on the real user surface, and audit the diff. The live lane is mandatory. Treat lane results as provisional until the coordinator independently audits the owner's self-proof, CI and babysit receipts against exact base/head SHAs and required pass predicates. Missing, stale or failed evidence blocks a clean verdict.

   A full swarm runs at code-ready and again for new behavior, a redesign or a large new diff. Minor fixes and rebases need an independent verifier at the new head, plus every invalidated lane. The patch-id and base-freshness rules in `playbooks/shipping.md` govern reuse. Send proven findings to the branch owner in one fix-forward, with a red test across the sites sharing the defect. A pre-existing trunk defect is recorded separately unless this PR copies or newly reaches it. Never fix another owner's branch yourself.
5. **Merge only what was verified on the base it lands on.** Green checks alone are not authorization. After verification starts, merge prep rebases onto current trunk, reports the new head and waits for required CI. Reaudit exact receipts. If trunk or the intended base moved, required integration, live and perf proof must cover the combined current base and PR head. Patch-id equality and disjoint paths never waive this local contract. A forge result is equivalent only when it names that exact combined tree and covers those lanes. Hold colliding work rather than endlessly rebasing.

   An owner may squash-merge its own PR only under the operator's explicit landing grant and the coordinator's clean verdict. Never bypass forge-enforced approvals. Operator-owned items wait for the operator. A fresh owner takes the next independent item.
6. **Audit the whole delegated tree.** A loosened gate or raised pinned budget needs independent proof and a fresh authorized countersign. Remove disabled or soft-failed checks rather than accepting them as protection. Use completion notifications or one bounded background heartbeat with available Codex tools; do not assume `/loop`, automatic wakeups or recurring execution permission. Re-read this playbook and the persisted objective at each audit. Judge agents by pushed branches, receipts and trails, not status prose. Repair missing records through their owners. Replace failed or genuinely stuck workers with fresh consolidated briefs; workers waiting on an approval are not stuck. A replacement never overlaps the old worker's write ownership.

   Audit until no delegated work remains, including after the last merge. Sweep post-merge failures and bot comments. A checkpoint that changed something for the operator catches them up per **ketchup**. An unchanged checkpoint stays quiet.
7. **Stand down immediately on stop.** Deliver the operator's zero-writes hold to every owner. Record current state and preserve briefs until explicit release.

**Reply:** use **ketchup** to report each PR's state and verdict, what merged, countersigns and their evidence, open operator gates, and real links to PRs and trails.
